# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Neovim plugin for editing a Logseq-format graph directly on disk: daily journal files, `[[Page]]` links, and block-based bullets, following the same file layout and `config.edn` conventions (e.g. `:export/bullet-indentation`, `:journal/file-name-format`) that Logseq itself uses. `lua/logsvim/graph.lua` is the layer responsible for reading/writing that format correctly.

## Commands

Run the full test suite:

```
nvim --headless -u tests/minimal_init.lua -c "PlenaryBustedDirectory tests/ {minimal_init = 'tests/minimal_init.lua'}"
```

Run a single test file:

```
nvim --headless -u tests/minimal_init.lua -c "PlenaryBustedFile tests/edit_spec.lua"
```

Tests use [plenary.nvim](https://github.com/nvim-lua/plenary.nvim)'s busted-style runner. `tests/minimal_init.lua` looks for plenary at `$PLENARY_PATH` or `~/.local/share/nvim/lazy/plenary.nvim`; set `PLENARY_PATH` if it's installed elsewhere. There is no separate lint/build step.

## Architecture

The plugin has no persistent daemon or server — everything runs synchronously in the Neovim process except the ripgrep-backed page index, which shells out via `vim.system`.

**Module map** (`lua/logsvim/`):
- `config.lua` — defaults + `setup()`. Tracks whether `root` was passed explicitly (`explicit_root`) vs. left to fall back to cwd, which `graph.resolve_root()` uses to decide whether to trust it outright. Also owns the `keymaps` table (action name -> key/list of keys/`false`) and `set_keymap(bufnr, name, rhs, desc)`, which `journal.lua`/`pages.lua` call instead of `vim.keymap.set` directly so mappings stay user-configurable.
- `graph.lua` — the graph-format layer: resolving which directory is "the graph" (`resolve_root`, memoized per-session), path helpers (`journal_dir`, `pages_dir`, `journal_path`), and the Logseq-format functions (`build_journal_block`, `append_block`, `sub_indent_for`, `guard_leading_dash`, `rename_page`). Also owns every write to disk: `write_lines_atomic` (temp file + rename, so nobody ever sees a half-written file), `write_lines_checked` (writes only if the file still holds the lines the caller based its edit on, otherwise returns the disk lines), and `merge_lines` (three-way merge via `git merge-file -p`, the same algorithm logsurf uses; nil on conflict or without git). `append_block`/`rename_page` re-apply their edit if the file changes between read and write.
- `index.lua` — the `[[Page Name]]` completion index: an in-memory table per root, backed by a JSON cache under `cache_dir` (filename = root path with `/` escaped to `%`) and refreshed asynchronously via `rg` scanning journals+pages for `[[...]]` plus `pages/*.md` filenames. `known_roots()` recovers previously-indexed graphs from cache filenames, used when cwd doesn't look like a graph root.
- `journal.lua` — the scrollable, editable journal view. Implements a virtual buffer under the `logsvim-journal://<root>` scheme (`BufReadCmd`/`BufWriteCmd` autocmds), lazy-loading batches of daily files newest-first as the user scrolls (`WinScrolled` → `maybe_load_more`). Each day's region is tracked by an extmark anchored to its `# <date>` header line; on write, only files whose region actually changed get rewritten to disk, and a background `index.refresh()` runs if anything changed. Each region's `original_lines` is the file version it's based on: a write is checked against it (`graph.write_lines_checked`), a concurrent change on disk is three-way merged into both file and buffer, and a conflict leaves that day unwritten and the buffer modified; `:w!` (`vim.v.cmdbang`) overwrites. `M.reload()` (on `BufEnter`, `FocusGained`, `:LogsvimReload[!]`) replaces unedited days with their disk content and only notifies for edited ones (`!` discards the edits).
- `schedule.lua` — finds Logseq task blocks anywhere in the graph (journals and pages) for the pseudo-pages `pages.lua` serves. `M.due(root, now)` finds `SCHEDULED:`/`DEADLINE:` blocks due today or earlier that aren't done (marker isn't `DONE`/`CANCELED`/`CANCELLED`), for the "Scheduled" pseudo-page. `M.by_marker(root, status)` finds every block currently carrying task marker `status` (one of `M.MARKERS`: `TODO`/`DOING`/`NOW`/`LATER`/`WAITING`/`IN-PROGRESS`/`DONE`/`CANCELED`/`CANCELLED`), one call per status pseudo-page. Both group matches by source file and hand each group's line array + header indices to `outline.group()` for context/indentation, returning `{ { name = <page/date>, kind = "journal"|"page", lines = {...} }, ... }`.
- `outline.lua` — shared block/ancestor/grouping helpers used by both `schedule.lua` and `pages.lua`: given a source file's lines and a list of "interesting" bullet-header line indices, `M.group()` reconstructs each header's ancestor chain (`M.ancestor_chain`) for context, merges headers that share an ancestor under it once instead of repeating it, absorbs a header already covered by another header's own subtree (`M.collect_block`) instead of duplicating it, and re-indents everything relative to its new position in that merged tree via `graph.sub_indent_for()` — fixing raw/orphaned indentation that would otherwise result from copying a block out of arbitrarily-deep source context. `M.header_for()` walks a non-bullet line (e.g. a SCHEDULED property line) up to the bullet it belongs to.
- `pages.lua` — the editable page view under `logsvim-page://<root>/<name>`, plus the "pseudo-pages" served under the same scheme/command with no `pages/<name>.md` file behind them: `PSEUDO_PAGES` maps `"Scheduled"` and each of `schedule.MARKERS` to a `schedule.lua` query, rendered fully read-only (no editable content region, `M.write()` skips the file-write/reindex step entirely) via `render_pseudo()`. A normal page renders the page's own `pages/<name>.md` contents (if any, editable) followed by every journal bullet that references `[[name]]`, grouped by date and, within each date, by shared ancestor context via `outline.group()` (read-only). `st.original_lines` is the page file's content as last rendered: `M.write()` skips the file entirely when the content region still equals it (so `:w` just to refresh references never clobbers an outside edit), and otherwise does the same checked write / merge / refuse / `:w!` as the journal. `M.reload()` re-renders an unedited page (content and linked references) and only notifies for an edited one. `goto_under_cursor` (bound to both `gd` and `<CR>` in journal and page buffers) follows either direction of reference: a `[[Page]]` link under the cursor opens that page (`open_under_cursor`) — including a pseudo-page name, since it's just another `logsvim-page://` buffer; failing that, the nearest `### <name>` heading above the cursor jumps to it (`goto_reference`) — a journal date for linked references, or either a journal date or another page for a pseudo-page's groups, per that buffer's `state[bufnr].heading_kind` map. `rename_under_cursor` (bound to `<leader>rn`, on a `[[Page]]` link) drives `graph.rename_page()` and then reloads any open journal/page buffers that would otherwise show stale text; renaming a pseudo-page name is rejected. `completion_names()` lists pseudo-pages that currently have something to show first (in `PSEUDO_PAGE_NAMES` order — `"Scheduled"`, then `schedule.MARKERS`), then every known real page name from `index.names()` (deduped against any collision); used by `:LogsvimPage`'s command-line completion (`plugin/logsvim.lua`) and the optional `telescope/_extensions/logsvim.lua` picker.
- `buffer.lua` — auto-attaches `edit.lua` keymaps + nvim-cmp completion to any real file under the graph's `journal_dir`/`pages_dir` (e.g. opened via quickfix or `gd`), since those don't go through `journal.lua`'s virtual buffer. Sets `autoread` on them and runs `:checktime` on `BufEnter`/`FocusGained`, so Neovim's own reload/W11 warning handles changes made elsewhere. Also has `keep_views(bufnr, fn)`, used by journal/pages to keep every window's cursor/scroll across a re-render.
- `edit.lua` — Logseq-style bullet editing: `<CR>` always starts a new line with the anchor line's indentation + `- ` (rather than trying to detect/continue bullets), and `<Tab>`/`<S-Tab>` in insert mode indent/dedent the current line using `config.options.indentation`'s unit.
- `cmp_source.lua` — nvim-cmp completion source for `[[Page]]` links, triggered on `[`, sourcing candidates from `index.names()`.

**Optional third-party integrations** (not required by the rest of the plugin, only loaded if the user's config asks for them): `cmp_source.lua` (above) for nvim-cmp, and `lua/telescope/_extensions/logsvim.lua` for telescope.nvim — registers a `pages` picker (`:Telescope logsvim pages`, or `require("telescope").extensions.logsvim.pages()`) listing `pages.completion_names()`'s candidates with a live preview via `pages.render()`; selecting one calls `pages.open()`.

**Virtual buffer schemes**: `logsvim-journal://<root>` (editable, `acwrite`) and `logsvim-page://<root>/<name>` (`acwrite`; only the page-content region is saved). Both are registered via `BufReadCmd` autocmds in `plugin/logsvim.lua`, which also defines the user commands (`:LogsvimPage`, `:LogsvimJournal`, `:LogsvimReindex`, `:LogsvimReload[!]`).

**Root resolution order** (`graph.resolve_root`): explicit `setup({root=...})` → `$LOGSVIM_ROOT` → cwd → cwd's parent → prompt among cached known roots. Resolved once per session and memoized; tests must call `require("logsvim.graph")._test.reset_resolved_root()` between cases (see `tests/helpers.lua`'s `temp_graph()`).

**Testing conventions**: `tests/helpers.lua`'s `temp_graph()` copies `tests/fixtures/test-graph/` into a fresh tempdir so tests can mutate files freely, then resets the memoized root. Modules expose test-only internals via a `M._test = {...}` table (e.g. `edit._test.shift_line`, `journal._test.state`) rather than making everything public API. `tests/minimal_init.lua` overrides `config.defaults.cache_dir` to a tempdir once for the whole run, so `index.refresh()`'s async cache writes (see `index.lua` above) never land in the real `~/.cache/logsvim` and pollute `known_roots()` with dead `/tmp/...` graphs — no individual spec file needs to set `cache_dir` itself unless it inspects the cache's contents directly (as `graph_spec.lua` and `index_spec.lua` do).
